<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| commit/PR text → LLM prompt (release-notes) | Untrusted commit messages/PR titles flow into the LLM prompt (prompt-injection vector) |
| grouped model → rendered markdown | Untrusted text rendered into changelog/release-notes markdown |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Tampering | LLM prompt injection via commit/PR text | mitigate | Commit/PR text is inserted as clearly-delimited data in the prompt; the deterministic skeleton (not the LLM) determines which entries appear, so a prompt-injected narrative cannot fabricate/omit changelog entries. The changelog path is LLM-optional and golden-tested with LLM off, bounding blast radius. |
| T-05-02 | Tampering | non-deterministic output breaking golden tests | mitigate | Deterministic render is a pure function of the grouped model; LLM polish is a separate skippable step; golden tests run with nil LLM (Pitfall 3). |
| T-05-03 | Information disclosure | model string / secrets in logs | mitigate | Pass `rc.Model` through; no token logged; reuse existing nil-tolerant LLM gateway (no new provider path — D-17). |
</threat_model>
