<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Spec-derived strings → Markdown output | Titles/summaries/descriptions/param names originate from an untrusted committed spec and are spliced into Markdown consumed by readers. |
| Spec content → inlined HTML JSON | The spec is serialized into a `<script>` block; non-deterministic key order would break golden tests (correctness, not security). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-07 | Injection | spec strings → Markdown (text/template no auto-escape) | mitigate | Apply `template.HTMLEscapeString` / explicit Markdown-control escaping to spec-sourced string fields before rendering (Task 2). |
| T-03-08 | Tampering/Integrity | non-deterministic HTML/MD output | mitigate | Sorted-key YAML→JSON for HTML (no `json.Marshal(map[string]any)`); sorted tag/path/op/param iteration for Markdown; golden + determinism tests enforce byte-identity (Tasks 1-2). |
| T-03-03 | Information Disclosure | CDN/external script in HTML | mitigate | Bundle inlined via go:embed; HTML contains no external `src=`/`cdn.redoc.ly`; `TestBuildRedocHTML_NoCDN` enforces (Task 1). |
</threat_model>
