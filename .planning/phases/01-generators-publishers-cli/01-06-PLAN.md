<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| generated section (commit/PR text) → release body / CHANGELOG.md PR | Untrusted text written into provider-rendered markdown |
| publisher → VCS write API (token) | Authenticated writes to release body + branch/PR |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Tampering | duplicate PR / PR spam on re-run | mitigate | Deterministic branch `cadoo/changelog/vX.Y.Z` + hidden marker key on ToRef enforce a single PR; TestSinglePR asserts exactly one PR across two runs (D-13). |
| T-06-02 | Tampering | clobbering user-written release body | mitigate | `SpliceReleaseBody` replaces only the inner marker block and preserves user content outside (D-12); TestSplicePreserves asserts it. |
| T-06-03 | Tampering | markdown/HTML injection into release body via commit text | accept | Cadoo content is wrapped in HTML-comment markers; body rendered as markdown by the provider; same posture as existing review summaries (RESEARCH Security). |
| T-06-04 | Denial of service | repeated writes when body unchanged | mitigate | No-op-if-unchanged guard (mirror applyPRBody) avoids redundant API writes. |
| T-06-05 | Availability | read-back failure during reconstruction | accept | On read-back failure, publisher logs and proceeds best-effort (may duplicate this run) rather than failing the whole run — matches ci.go priorStore degrade. |
</threat_model>
