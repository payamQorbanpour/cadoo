<objective>
Build the template subsystem: embedded preset templates (`go:embed`), a loader that resolves a
repo-provided `template:` override from the release tag's tree (falling back to the embedded preset),
and a render function that executes a Go `text/template` against the `ReleaseContext` + grouped
change model. This is net-new infrastructure — `go:embed` and `text/template` have zero prior usage
in the repo.

Purpose: REQ-configurable-templates — two configurability layers (presets out of the box, custom
override files for full control). Generators (Plan 05) call this to render their output.

Output: `internal/releasedocs/template/template.go`, `presets/*.tmpl`, and tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repo `template:` override file (tag tree) → text/template execution | Operator-authored template from the release tag's own tree is parsed and executed |
| grouped change model (commit/PR text) → template data | Untrusted commit/PR text rendered through the template |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering / EoP | text/template override execution | mitigate | Use `text/template` with NO custom FuncMap exposing `os`/`exec`/filesystem; the only data is ReleaseContext + grouped model. Template author = repo owner (trusted, loaded from their own tag tree), so no cross-tenant injection surface — but the no-OS-funcs rule is enforced regardless (RESEARCH Security V5). |
| T-03-02 | Tampering | override loaded from wrong ref | mitigate | Override fetched from `rc.ToRef` tree only, via FetchFileFromRef (never `main`/HEAD) — Pitfall 2; asserted by TestTemplateOverride. |
| T-03-03 | Information disclosure | markdown/HTML injection via commit text in rendered output | accept | Output is markdown rendered by the provider; Cadoo content is wrapped in HTML-comment markers by the publishers (Plan 06). text/template (not html/template) is correct because output target is markdown, not HTML pages. |
</threat_model>
