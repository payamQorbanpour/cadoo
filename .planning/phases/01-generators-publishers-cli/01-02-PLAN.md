<objective>
Build the ReleaseContext builder and the shared grouped change model — the deterministic, pure
transform layer that every generator consumes. This includes semver bump computation (via
`golang.org/x/mod/semver`), the Conventional-Commit parser (hand-rolled), label-based grouping,
fixed-order section sorting (golden-test enabler), and the `Enabled(cfg, bump)` gate logic.

Purpose: This is the deterministic core that makes changelog golden-file tests possible and gates
per-artifact toggles (REQ-per-artifact-toggles). It is pure (no I/O beyond the range-read
type-assert) and therefore the highest-value TDD target in the phase.

Output: `internal/releasedocs/context.go`, `internal/releasedocs/changemodel.go`, and their tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| VCS commit/PR text → grouped change model | Untrusted commit messages, PR titles/bodies, and labels flow into the model that later renders markdown |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | grouped change model (markdown injection) | accept | Commit/PR text is rendered as markdown by the provider downstream; Cadoo wraps its content in HTML-comment markers (handled in publishers). No code execution here; the model is plain data. Same trust posture as existing review summaries. |
| T-02-02 | Denial of service | range read of very large commit ranges | accept | Range size bounded by the operator-chosen FromRef..ToRef; pagination handled by the adapter. No unbounded recursion in the pure transform. |
| T-02-03 | Tampering | semver parsing of malformed tags | mitigate | Normalize/validate tags before `semver.Compare`; malformed tags yield BumpNone or a clear error rather than a panic (covered by TestBump edge rows). |
</threat_model>
