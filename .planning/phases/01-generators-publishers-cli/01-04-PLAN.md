<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| adapter → VCS REST API (authenticated) | Token-authenticated calls write release bodies / open PRs/MRs |
| VCS API response → normalized vcs types | Provider response data normalized into Commit/MergedPR/Release |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Information disclosure | token handling in adapters | mitigate | Tokens stay inside `*Adapter` (built in `New`), never logged — consistent with existing adapter methods; no token field added to the capability interfaces. |
| T-04-02 | Tampering | writing to an unintended branch/PR | mitigate | Branch name + single-PR/MR are passed by the publisher (deterministic `cadoo/changelog/vX.Y.Z`); adapter performs only the requested write. Idempotency invariant asserted in Plan 06. |
| T-04-03 | Spoofing | wrong glab import path resolving to a different module | mitigate | Use the exact `gitlab.com/gitlab-org/api/client-go` path (Pitfall 1); `make build`/`make vet` catch a wrong path; grep assertion in verify. |
| T-04-04 | Repudiation | unconfirmed v66/v0.115 signatures | mitigate | Confirm method signatures via `go doc` before coding (A2/A3); httptest tests exercise the real call paths. |
</threat_model>
