<objective>
Part B — make thread resolution and anchor location first-class dedup inputs so a resolved
thread stays gone even if the LLM rewords the finding. This directly kills the "resolve 2 → 6
come back" loop.

Purpose: Today `vcs.PriorInline` carries `Resolved` but never the anchor line, and
`NewFromPrior` drops `Resolved` entirely — so a user-resolved thread carries zero suppression
weight and a reworded restatement sails right back in. This plan captures the anchor line in
both adapters, carries Resolved + Line into the seeded store record, and widens
`memoryStore.has` so resolved priors suppress reworded duplicates via line-overlap or a lower
Jaccard threshold — scoped to (tool, file) and overlapping lines so a genuinely different
finding elsewhere is still posted.

Output: PriorInline.Line/EndLine, findingRec.Resolved/Line, ResolvedSuppressThreshold const,
widened memoryStore.has, NewFromPrior seeding, anchor-line capture in both adapters, and
table-driven suppression tests. CI-mode (memory store) only per SPEC — the DB HasFinding path
is unchanged (no resolved column; no migration).
</objective>
