<objective>
Part C orchestration + the convergence fixed-point test — wire the incremental change set into
the review pipeline and prove the loop converges. This depends on Plan 01 (resolveStalePriors
direct-compare + reviewer.go) and Plan 03 (DiffBetweener, PriorReview.LastReviewedSHA,
tools.Input fields, marker round-trip).

Purpose: With the infra in place, the orchestrator must (1) recover LastReviewedSHA from the
seeded store, (2) when it is a non-empty ancestor of head, call DiffBetween and feed inline
tools only the incremental change set while summary tools keep the full view, (3) gate
resolveStalePriors so priors on untouched files persist instead of being resolved (the critical
interaction from the SPEC). Together with Parts A+B this reaches a fixed point: a re-run against
an unchanged head posts 0 new and resolves 0 existing.

Output: Store.LastReviewedSHA() method, the incremental dispatch block in Run, the
changeSet-scoped resolveStalePriors, and the fixed-point + incremental + fallback integration
tests (the most important verification of the whole phase, SC-1).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LastReviewedSHA (from store, parsed from attacker-influenceable comment) → DiffBetween | Controls which intra-repo diff is fetched |
| Incremental change set → resolveStalePriors gate | Determines which priors may be resolved; a wrong set could either resolve too much or skip review of changed code |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-C4 | DoS / Tampering | Same-commit or self-referential SHA causing a needless provider call or odd diff | mitigate | Guard `sha != "" && sha != pr.HeadSHA` before calling DiffBetween (Task 2, T-08-C2); equal SHA short-circuits to the empty/full path without a provider round-trip |
| T-08-C5 | Tampering / Correctness | Non-ancestor SHA silently SKIPPING review of genuinely changed code | mitigate | `high`, blocking. DiffBetween returns (nil,nil) on non-ancestor → full-review fallback (IsIncrementalRun=false), so all changed code is reviewed. Asserted by TestDiffBetweenFallbackOnNonAncestor; empty-vs-nil semantics per Pitfall 4 |
| T-08-C6 | Correctness | Incremental scoping resolving priors on untouched code (re-introducing churn) | mitigate | resolveStalePriors skips priors whose File is not in the change set when incrementalRun (Task 2, SPEC critical interaction); asserted by TestCIModeIncrementalChangedLines |
| T-08-C7 | Tampering | Bypassing the Posted dedup store with a new posting path | mitigate | Pitfall 3: incremental logic only changes WHICH files are in tools.Input; posting still flows through postInline → HasFinding; acceptance criterion greps that no new PostInlineComments path is added |
| T-08-SC | Tampering | npm/pip/cargo installs | accept | No package installs (RESEARCH audit SKIPPED — no new deps) |
</threat_model>
