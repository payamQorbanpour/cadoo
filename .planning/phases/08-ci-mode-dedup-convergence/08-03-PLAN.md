<objective>
Part C infrastructure — the stateless plumbing for incremental review: the `reviewed-sha`
marker (render + validated parse), `PriorReview.LastReviewedSHA`, the `DiffBetweener` optional
provider capability implemented in both adapters, `LastReviewedSHA` parse-back in both adapters,
and the additive `tools.Input` incremental-context fields. This plan is pure infrastructure —
the orchestrator wiring and fixed-point integration test land in Plan 04.

Purpose: Enable a stateless CI run to know what it last reviewed (SHA persisted in the summary
wrapper) and fetch only the `lastReviewedSHA..head` diff, imposing a structural ceiling on
thread growth. The marker is attacker-influenceable content read back from the PR/MR, so
`ParseReviewedSHA` MUST validate it is exactly 40 hex chars before use (ASVS V5).

Output: marker helpers + tests, PriorReview field, DiffBetweener interface + both impls +
compile-time assertions, LastReviewedSHA parse in both adapters, renderConsolidated signature
change with call-site updates, and tools.Input incremental fields. No orchestrator dispatch
logic here (Plan 04).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PR/MR summary comment body → ParseReviewedSHA | Attacker-influenceable: anyone who can comment could embed a forged `<!-- cadoo:reviewed-sha:... -->` marker |
| reviewed-sha value → DiffBetween API call | The parsed SHA selects WHICH diff to fetch within an already-authorized repo |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-C1 | Tampering / Injection | Malformed or forged `reviewed-sha` marker in a PR comment body | mitigate | `ParseReviewedSHA` validates the value is exactly 40 hex chars (`^[0-9a-f]{40}$`) before returning it; invalid → "" → full-review fallback (Task 1, ASVS V5). `high` severity, blocking |
| T-08-C2 | Information Disclosure | Forged SHA pointing DiffBetween at an arbitrary commit | mitigate | DiffBetween is invoked with the already-authorized `pr.RepoFullName`; the SHA only controls which intra-repo diff is fetched, not which repo; non-ancestor/unknown SHA → API error → (nil,nil) fallback (Task 2) |
| T-08-C3 | DoS | Marker grep breakage hiding the summary comment | mitigate | Pitfall 5: marker placed INSIDE the wrapper after SummaryWrapperBegin so the existing `strings.Contains(body, SummaryWrapperBegin)` detection still triggers (Task 1; asserted by TestRenderConsolidatedEmbedsReviewedSHA) |
| T-08-SC | Tampering | npm/pip/cargo installs | accept | No package installs (RESEARCH audit SKIPPED — reuses existing go-github / go-gitlab) |
</threat_model>
