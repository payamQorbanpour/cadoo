# Cadoo review guide

Cadoo is a multi-tenant AI code reviewer (Go) that posts inline comments and
check-runs to GitHub/GHES/GitLab. Optimize reviews for **correctness and
architectural integrity over style nits** — the project already has linters for
formatting.

## What we care about most

- **Idempotency.** The review pipeline must be safe to re-run on every resync.
  Flag any new comment-posting path that bypasses the dedup layer
  (`Dispatcher.Posted` / `internal/findings.Store`) — summaries are edited in
  place, inline findings are deduped by fingerprint, never re-posted.
- **Error wrapping.** Errors crossing a package boundary must be wrapped with
  `%w` and context. Silently swallowed errors are always worth a comment.
- **Multi-tenancy.** Every table and query carries `org_id`. Flag any new
  schema, query, or store method that drops tenant scoping — there are no
  single-tenant shortcuts, even in self-host paths.
- **Tests.** New behavior needs a test; bug fixes need a regression test.
  Prefer table-driven tests; use `t.Helper()` in helpers.

## Architectural boundaries (flag violations as blocking)

- The orchestrator and tools depend **only** on the `vcs.Provider` interface.
  Never import a concrete provider package (`internal/vcs/github`,
  `internal/vcs/gitlab`) from outside `internal/vcs/`.
- Go code talks to LLMs only through the LiteLLM gateway (`internal/llm`).
  Reject provider-specific (OpenAI/Anthropic/Bedrock) branching in Go.
- Don't reintroduce the `internal/kb` → `internal/llm` cycle; query distillation
  lives in `internal/kb/querydistill` for exactly this reason.
- The consolidated-comment / PR-body wrapper format lives in
  `internal/orchestrator/consolidate.go` — don't reinvent the
  `<!-- cadoo:* -->` markers elsewhere.

## Areas with extra scrutiny

- `.cadoo.yaml` / `.cadoo.md` config is loaded from the **PR head SHA**, never
  from `main`. Flag any config read that uses the base branch.
- `db/migrations/**` — forward-only. CI runs `up → down → up`, so every
  migration must round-trip cleanly. Call out any non-reversible step or a
  `DROP COLUMN` without a documented forward-only rationale.
- Every **exported** Go symbol needs a docstring (`exported` revive rule is on,
  even though `package_comments` is off).
- CI-mode (`cadoo ci`) is **stateless** — no DB, no KB, no learnings. Flag any
  CI-mode path that assumes those are present.

## Tone

Be direct and specific. Quote the exact line and propose a concrete fix rather
than asking an open-ended question. Don't restate what the diff obviously does,
and don't flag pure formatting — `golangci-lint` owns that.
